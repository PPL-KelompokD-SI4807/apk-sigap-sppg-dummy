## Hal yang sudah aman (diverifikasi)
1. **IDOR lintas investor.** Header SPPG investor lain/terhapus/dicabut menghasilkan 403 di semua rute, termasuk rute pengecualian (`auth.*`, `sppg-saya`). `SppgScope`, `BaseSppgPolicy::sameSppg`, `SppgBound` (AI), `SppgController@index`, `RekapHarianController@ringkasan`, `KeuanganController@ringkasan`, dan agregat semuanya memakai `sppgAktifId()`. `?sppg_id=` hanya dihormati untuk Admin. Binding model berjalan setelah `ResolveSppgAktif`. Investor lain (sppg_id null) tidak terlihat (404). Tidak ada rute ekspor.
2. **Validasi header.** Hanya `^[1-9][0-9]*$` yang diterima. Nilai non-numerik, negatif, nol di depan, ganda (`"1, 2"`), dan header kosong menghasilkan 0 atau null, lalu fail closed. Hasil dihitung ulang tiap permintaan dari pivot (`DB::table`, tanpa rekursi scope). Instance `scoped` di-reset middleware dan dijaga `spl_object_id(request)`, dan Laravel mem-flush instance scoped per job queue/permintaan Octane. Di luar middleware (publik, pra-login, webhook, job) `SppgAktif` sendiri mengembalikan null untuk SPPG yang tidak sah. Untuk peran non-investor, header berbeda menghasilkan 403 dan SPPG mereka tidak pernah berubah. Perilaku Admin tidak berubah.
3. **Penulisan oleh investor.** Matriks investor hanya R, dan `Rbac::letters` membuang C/U/D walau matriks salah isi. Tes menyapu seluruh rute non-GET `api/v1` dan hanya mendapat 403/404. `StoreLampiranRequest` memakai `Rbac::readOnly`. `DraftService::create`, `WriteDraftTool::isAvailableFor`, dan `AiDraftConfirmer` menolak investor. Ability token hanya `auth:penuh` + `modul:R` (ability modul bersifat informatif dan tidak dipakai untuk otorisasi).
4. **Agregat.** Hanya hitungan: tanpa nama, kelas, catatan alergi, atau ID penerima. Data disaring `sppg_id` + `deleted_at` dan dijaga `viewAgregat`. `penerima-manfaat` index/show untuk investor menghasilkan 403. Resource keuangan/mutu/rekap/bahan baku hanya memuat nama staf dan pemasok, tanpa data penerima.
5. **Agen AI.** Investor hanya ditawari tool baca (diuji). Di bot, investor dengan >1 SPPG atau tanpa SPPG ditolak sebelum LLM dipanggil. Tidak ada parameter tool yang dapat mengganti SPPG, karena `SppgBound` memaksa SPPG aktif. Nama penerima disamarkan menjadi inisial, dan investor tidak punya tool penerima manfaat. Callback bot tidak menjalankan aksi.
6. **Endpoint Admin kepemilikan.** Dijaga `UserPolicy::kelolaKepemilikan` (isAdmin + update) di Form Request dan controller (investor/kepala menghasilkan 403). Validasi mencakup peran target investor (juga diperiksa ulang di bawah `lockForUpdate`), `exists` + `whereNull(deleted_at)`, `distinct`, dan `max:100`. Hanya field tervalidasi yang dipakai (tanpa mass assignment). Audit mencatat sebelum/sesudah/ditambah/dihapus. Pencabutan berlaku pada permintaan berikutnya. Perubahan peran dari investor menghapus pivot di dalam transaksi controller.
7. **Regresi peran lain.** `users.sppg_id` investor dipaksa null di `PenggunaRequest`, `StoreUndanganRequest`, `InvitationService`, `UserAccountService`, dan dev login. Daftar pengguna investor hanya berisi profilnya sendiri. Penerima notifikasi (`usersWithRoles`) tidak menyertakan investor. Scope `users` untuk kepala SPPG tidak berubah.
8. **Frontend.** Pilihan SPPG disimpan di `sessionStorage` dan dibersihkan saat logout serta saat menerima 403/409 dari server. Komponen baru tidak memakai `innerHTML`.
