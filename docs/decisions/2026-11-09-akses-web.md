# ADR: Akses web SiGAP SPPG di akar domain (R-04)

- Tanggal: 2026-11-09 (diusulkan) · 2026-11-10 (diterima)
- Status: **Diterima** 2026-11-10 oleh pengguna, dengan jawaban Q1-Q5 di bawah; belum ada kode (implementasi mengikuti jadwal gelombang di rencana)
- Tier: T3 (autentikasi, sesi, guard, CSRF, header keamanan)
- Rencana: `docs/plan/2026-11-09-r04-web.md`
- Fitur terkait: No 1 Data Pengguna (Login Akun); fitur 2-16 hanya mendapat kanal akses baru, tanpa perubahan ruang lingkup
- Acuan: keputusan pengguna R-04 (6 butir), ADR `2026-11-07-sesi-login-90-hari.md` (PR #55), rencana `docs/plan/2026-10-26-r03-login-kredensial.md` (R-03), PR #48 (daftar ulang akun terhapus), `routes/api.php`, `config/sanctum.php`, `config/kredensial.php`, `docker/nginx/snippets/*`.
  Berkas acuan `claude/revisi-r04-akses-web.md` dan `claude/revisi-r03-login-kredensial.md` **tidak tersedia di repo**; isinya tidak diasumsikan.

## Konteks

Saat ini SiGAP hanya dapat dipakai lewat Telegram Mini App (`/miniapp/`) dan bot. Login dua lapis: initData Telegram (HMAC) memberi token pra-login, lalu username/no telepon + sandi (+ token 6 digit dari bot untuk perangkat baru) memberi token Sanctum `auth:penuh` yang dikirim sebagai Bearer dan disimpan di `localStorage`. Sanctum dikonfigurasi tanpa guard sesi (`'guard' => []`), dan `EnsureTokenAbility` sudah menolak token transien (cookie SPA).

Pengguna meminta akses web di akar `https://sigapsppg.app/` dengan keputusan:
1. Faktor kedua di web = kode sekali pakai dari bot ke Telegram pengguna.
2. Semua fitur kerja (CRUD, dasbor, persetujuan, unggah foto, layar draf AI) tersedia di web; chat Agen AI di web menyusul; notifikasi tetap lewat bot.
3. Web di akar domain; Mini App tetap `/miniapp/`.
4. Tidak ada registrasi mandiri; akun tetap lewat undangan Admin + aktivasi di bot.
5. Opsi "Ingat browser ini 30 hari" (pilihan B): browser tepercaya cukup sandi, tanpa kode.
6. Sesi web mengikuti aturan PR #55. Batas sesi semula diusulkan gabungan 5; diubah oleh Q2 menjadi kuota terpisah (5 Mini App + 3 web) dan ditambah idle 12 jam untuk web (Q3).

### Keputusan pengguna atas pertanyaan terbuka (2026-11-10)
| No | Keputusan | Bagian ADR yang berubah |
|---|---|---|
| Q1 | Admin **tidak boleh** memakai "Ingat browser ini"; Admin selalu memasukkan kode. | Keputusan 4 dan 6 |
| Q2 | Kuota sesi **terpisah**: maks 5 sesi Mini App + maks 3 sesi web. Browser tepercaya tetap maks 5 sendiri (bukan sesi). Mengganti butir 6 "batas 5 sesi gabungan". | Keputusan 1 |
| Q3 | Sesi web mendapat **batas idle 12 jam**, kecuali sesi dari browser tepercaya. Aturan lain tetap: 90 hari sliding, Admin 30 hari, absolut 180 hari. | Keputusan 1, A10 |
| Q4 | Cukup alur yang ada (nonaktifkan -> hapus -> undang ulang); tidak ada fitur "ganti akun Telegram" sekarang. Wajib tes bahwa username/no telepon baris terhapus lunak tidak menghalangi akun baru. Pemeriksaan 2026-11-10: **menghalangi** -> tugas perbaikan R04-13 (T3). | Keputusan 4 butir 7 |
| Q5 | CAPTCHA proof-of-work buatan sendiri tanpa pihak ketiga; **tidak dipasang saat rilis awal**. | Keputusan 10, A4 |

Keputusan 3 (web di akar domain) tetap; tinjauan keamanan R04-11 menilai ulang risiko satu origin dengan Mini App dan boleh merekomendasikan subdomain (keputusan akhir pada manusia).

Perbedaan mendasar dengan Mini App: di web **tidak ada initData**, sehingga endpoint login web bersifat publik dan identitas pengguna hanya berasal dari isian. Ini membuka permukaan baru untuk enumerasi akun, brute force sandi, dan DoS penguncian akun.

## Model ancaman dan pengaman

| No | Ancaman | Skenario | Pengaman |
|---|---|---|---|
| A1 | Pencurian sesi/cookie | XSS membaca token; malware/ekstensi; cookie terkirim lewat HTTP | Token sesi web hanya di cookie `__Host-sigap_sesi` (HttpOnly, Secure, SameSite=Strict, Path=/, tanpa Domain) sehingga tidak terbaca JS dan terikat ke host persis; HSTS; nilai disimpan ter-hash (SHA-256, bawaan Sanctum); masa 90/30/180 hari PR #55; pencabutan seketika (hook `User`); daftar sesi + cabut satu; notifikasi bot pada setiap login web baru. Token web ber-ability `klien:web` **ditolak bila dikirim sebagai Bearer**, dan token Mini App ditolak bila dikirim sebagai cookie. |
| A2 | Pencurian token browser tepercaya | Cookie `__Host-sigap_tb` disalin dari komputer bersama/malware | Token hanya melewati **kode**, sandi tetap wajib; acak 256-bit, disimpan SHA-256 (selektor + validator, `hash_equals`); terikat satu `user_id` (cookie milik A tidak berlaku untuk login B, tanpa pesan pembeda); berlaku tetap 30 hari sejak kode terakhir (tidak bergeser); maks 5 per pengguna; dicabut otomatis (lihat Keputusan 6); sesi yang dibuat lewat jalur lewati-kode tidak melewati `berlaku_sampai` browser itu dan ikut dicabut bila browser dicabut; notifikasi bot pada login lewat browser tepercaya. |
| A3 | CSRF | Situs lain memicu POST/PUT/DELETE memakai cookie korban; login CSRF | Tiga lapis: (1) SameSite=Strict; (2) `Origin` wajib sama persis dengan `https://sigapsppg.app` untuk metode pengubah (Origin kosong ditolak); (3) header `X-CSRF-Token` = HMAC(kunci turunan APP_KEY, id sesi atau id pra-login) + header `X-Sigap-Klien: web` (memaksa preflight lintas origin). Token CSRF dikirim di badan JSON dan disimpan di memori JS, bukan cookie terbaca. CORS: `config/cors.php` dipublikasikan dengan `allowed_origins` kosong dan `supports_credentials=false` (saat ini memakai default framework `*`). |
| A4 | Brute force sandi | Penebakan sandi dari internet tanpa initData | Respons langkah 1 seragam (lihat Keputusan 4) sehingga benar/salahnya sandi tidak terlihat tanpa kode; batas laju per IP, per identitas ter-normalisasi, dan global; **penguncian kanal web terpisah** dari Mini App (5 gagal -> 15 menit, berulang dalam 24 jam -> 60 menit); CAPTCHA tidak ada di rilis awal (Q5; Keputusan 10); daftar sandi umum R-03 tetap berlaku. |
| A5 | Brute force kode | Menebak 6 digit | Kode ter-hash (`TokenSekaliPakaiService::hashKode`), 5 menit, sekali pakai, maks 5 percobaan per tantangan, maks 3 kirim ulang dengan jeda 60 detik, maks 5 tantangan per 30 menit (nilai `config/kredensial.php` yang ada); penyerang harus sudah tahu sandi. Peluang maksimum ~25/10^6 per 30 menit. |
| A6 | Pengambilalihan akun Telegram | Penyerang menguasai akun Telegram korban sehingga menerima kode | Sandi tetap wajib (kode saja tidak cukup); pesan kode menyebut "MASUK WEB", browser, waktu, dan domain resmi, dengan tombol "Bukan saya" yang membatalkan tantangan dan dicatat di audit; pemulihan lewat Admin: nonaktifkan akun (mencabut semua sesi web, Mini App, dan browser tepercaya) lalu alur undangan/daftar ulang (Keputusan 8); panduan pengguna mengaktifkan verifikasi dua langkah Telegram. |
| A7 | Enumerasi akun | Membedakan akun ada/tidak, terkunci, nonaktif | Langkah 1 selalu `200 {langkah: "kode", tantangan_id}` dengan bentuk, header, dan waktu sama (hash sandi tiruan untuk akun tak dikenal); verifikasi kode selalu "Kode salah atau kedaluwarsa"; tidak ada "lupa sandi" di web (tetap di Mini App + persetujuan Admin); rate limit per IP. |
| A8 | XSS | Skrip asing berjalan di origin `sigapsppg.app` | CSP web **ditegakkan** penuh, `script-src 'self'` tanpa telegram.org; web tidak memuat `telegram-web-app.js`; renderer `h()` tanpa `innerHTML` + pemindai statis (berlaku juga untuk kode web); Trusted Types Report-Only. Catatan: Mini App dan web **satu origin**; XSS di salah satunya dapat menunggangi sesi web pada browser yang sama. Lihat Konsekuensi. |
| A9 | Clickjacking | Halaman web dibingkai situs lain | `frame-ancestors 'none'` + `X-Frame-Options: DENY` untuk `/`; header `/miniapp/` (frame-ancestors Telegram) **tidak berubah**. |
| A10 | Komputer bersama | Pengguna lupa keluar di warnet/komputer kantor | Kotak "Ingat browser ini" default mati + peringatan; tombol Keluar jelas; daftar sesi dan "keluar dari semua perangkat"; notifikasi bot setiap login web; **batas idle 12 jam** untuk sesi web yang bukan dari browser tepercaya (Q3), sehingga sesi yang lupa ditutup di warnet berakhir paling lama 12 jam setelah terakhir dipakai; Admin tidak dapat memakai browser tepercaya (Q1) sehingga sesi web Admin selalu terkena idle 12 jam. |
| A11 | Phishing real-time (tambahan) | Situs tiruan meneruskan sandi + kode | Pesan bot menyebut domain resmi dan "jangan masukkan di situs lain"; notifikasi login baru; passkey/WebAuthn dicatat sebagai pekerjaan lanjutan (di luar R-04). |
| A12 | DoS penguncian (tambahan) | Penyerang sengaja salah sandi agar korban terkunci | Penguncian web tidak memengaruhi Mini App (penyerang tidak punya initData korban); notifikasi bot "masuk web dikunci sementara" maks 1 kali/jam. |

## Keputusan (diterima 2026-11-10)

### 1. Dua jalur autentikasi, satu jenis token
- **Mini App (tidak berubah):** `Authorization: Bearer <id|secret>`, token Sanctum `auth:penuh` + ability peran, di `localStorage`. Guard cookie Sanctum tetap mati (`config/sanctum.php` `'guard' => []`). **Tidak memakai** mode stateful Sanctum, karena (a) permintaan Mini App dari origin yang sama akan ikut dianggap stateful dan terkena CSRF, dan (b) token transien tidak membawa ability `auth:penuh`.
- **Web (baru):** token yang sama jenisnya (baris `personal_access_tokens`, ability `auth:penuh` + `klien:web` + ability peran), tetapi **dikirim hanya lewat cookie** `__Host-sigap_sesi`. Middleware baru mengubah cookie menjadi token sebelum `auth:sanctum`. Dengan begitu `SesiService` (sliding 90 hari, Admin 30, absolut 180, batas sesi, pencabutan) dan semua Policy/RBAC/`ResolveSppgAktif` dipakai ulang tanpa salinan.
- **Batas tegas:**
  - Ada header `Authorization` -> hanya Bearer dievaluasi; cookie web diabaikan. Bearer tidak sah tetap 401 walaupun cookie sah.
  - Token ber-`klien:web` lewat Bearer -> 401. Token tanpa `klien:web` lewat cookie -> 401.
  - Jalur cookie wajib lolos pemeriksaan CSRF/Origin (A3); jalur Bearer tidak disentuh.
  - Rute `_public` (`auth/telegram`) dan `_pra-login` Mini App tidak menerima cookie web. Rute login web berada di prefiks terpisah `api/v1/web/auth/*` dengan throttle sendiri.
  - Penguncian, penghitung gagal, dan batas laju web terpisah dari Mini App.
- **Interaksi PR #55 - kuota sesi (Q2):** kuota **terpisah per jenis**: maks 5 sesi Mini App (batas keras `MAKS_SESI_KERAS` yang ada) dan maks 3 sesi web (batas keras baru di kode; env hanya boleh mengetatkan). Login Mini App ke-6 mencabut sesi Mini App yang paling lama tidak dipakai; login web ke-4 mencabut sesi web yang paling lama tidak dipakai; satu jenis tidak pernah mencabut sesi jenis lain, dan sesi yang sedang login tidak ikut dicabut. Browser tepercaya bukan sesi dan memiliki batas sendiri (maks 5).
- **Interaksi PR #55 - masa sesi (Q3):** sesi web biasa (token `klien:web` tanpa `browser_tepercaya_id`) berakhir setelah **12 jam tidak dipakai**, selain tetap dibatasi 90 hari sliding (Admin 30) dan absolut 180 hari. Sesi web yang terbit lewat browser tepercaya dikecualikan dari idle 12 jam, mengikuti 90 hari sliding, dan tidak melewati `berlaku_sampai` browser itu. Sesi Mini App tidak berubah. Agar idle akurat, jeda tulis `last_used_at` untuk token web <= 15 menit. Cookie sesi persisten dengan `Max-Age` mengikuti `expires_at` dan diperbarui saat masa bergeser (sejalan dengan jeda tulis). Server tetap penentu; cookie hanya pembawa.
- **Interaksi perangkat tepercaya bot (Mini App):** tidak dicampur. Browser tepercaya web memakai tabel baru `browser_tepercaya` (migrasi aditif). Login web tidak membuat atau memakai baris `perangkat_tepercayas`, dan sebaliknya. Kepercayaan perangkat Mini App 180 hari tidak berubah.

### 2. Cookie
| Cookie | Isi | Atribut | Umur |
|---|---|---|---|
| `__Host-sigap_pra` | id pra-login acak (mengikat CSRF dan tantangan sebelum login) | HttpOnly, Secure, SameSite=Strict, Path=/ | 15 menit |
| `__Host-sigap_sesi` | token Sanctum `id\|secret` (klien:web) | HttpOnly, Secure, SameSite=Strict, Path=/ | = `expires_at` sesi |
| `__Host-sigap_tb` | `selektor.validator` browser tepercaya (256-bit) | HttpOnly, Secure, SameSite=Strict, Path=/ | tetap 30 hari |

Prefiks `__Host-` mewajibkan Secure, Path=/, dan tanpa Domain, sehingga subdomain tidak dapat menimpanya. Pengembangan lokal tanpa HTTPS memakai nama tanpa prefiks lewat config (bukan env bebas), dan tidak pernah di produksi. Setelah login berhasil, `__Host-sigap_pra` dihapus dan token CSRF baru diikat ke id sesi (mencegah fiksasi sesi).

### 3. Domain tepercaya dan CORS
Satu origin: `https://sigapsppg.app` (dari `APP_URL`). Tidak ada CORS untuk `/api`. `SANCTUM_STATEFUL_DOMAINS` tidak dipakai karena guard stateful tetap mati. Daftar origin diizinkan untuk pemeriksaan `Origin` berasal dari config, bukan dari header `Host`.

### 4. Alur login web
1. `GET /api/v1/web/auth/csrf` -> set `__Host-sigap_pra`, balas `{csrf}`.
2. `POST /api/v1/web/auth/masuk {identitas, password}`:
   - Normalisasi identitas (username huruf kecil; no telepon ke format kanonik yang sama dengan R-03).
   - **Jika** cookie `__Host-sigap_tb` sah, milik akun yang sama, belum lewat 30 hari, belum dicabut, pengguna **bukan Admin** (Q1), **dan** sandi benar -> terbitkan sesi web, `200 {langkah: "selesai"}`, notifikasi bot "Login web dari browser tepercaya ...". Sandi salah pada browser tepercaya sah -> `422` "Identitas atau sandi salah" dan dihitung gagal (pemilik cookie sudah terikat ke akun ini, jadi tidak ada enumerasi baru).
   - **Selain itu** selalu `200 {langkah: "kode", tantangan_id}` dengan bentuk dan waktu seragam. Kode 6 digit dikirim ke `users.telegram_id` dari DB **hanya** bila akun ada, aktif, tidak terkunci di kanal web, dan sandi benar. Untuk kasus lain `tantangan_id` tiruan tidak tersimpan dan tidak ada pesan terkirim. UI: "Bila data benar, kode telah dikirim ke Telegram Anda. Tidak menerima kode dalam 1 menit? Periksa kembali sandi."
3. `POST /api/v1/web/auth/kode {tantangan_id, kode, ingat_browser}` -> sukses: hapus tantangan, terbitkan sesi web (cookie), dan bila `ingat_browser=true` dan pengguna bukan Admin (Q1; untuk Admin nilai ini diabaikan tanpa galat), buat/ganti browser tepercaya (berlaku 30 hari dari sekarang, browser lama yang sama dicabut). Gagal apa pun -> `422` "Kode salah atau kedaluwarsa." (seragam).
4. `POST /api/v1/web/auth/kode/kirim-ulang {tantangan_id}` -> respons seragam.
5. Pesan bot memakai jenis tantangan baru `masuk_web` dan berbunyi jelas berbeda dari kode Mini App (menyebut "MASUK WEB", browser ringkas dari User-Agent, waktu WIB, domain resmi), dengan tombol "Bukan saya" (membatalkan tantangan dan mencatat audit; tidak mengunci akun agar tidak menjadi alat DoS).
6. **Lupa sandi:** tidak ada di web. Layar masuk menautkan petunjuk "Buka Mini App SiGAP di Telegram -> Lupa password" (alur R-03: permintaan ke Admin -> persetujuan -> sandi baru + token bot).
7. **Kehilangan akses Telegram:**
   - Akun Telegram masih ada tetapi HP hilang: masuk Telegram di perangkat baru; kode tetap sampai. Pengguna meminta Admin mencabut sesi lama (`cabutSesiOlehAdmin`) atau memakai "keluar dari semua perangkat".
   - Akun Telegram hilang atau diambil alih: Admin menonaktifkan akun (mencabut semua sesi, browser tepercaya, dan tautan bot). Untuk akun Telegram baru, saat ini hanya ada alur yang sudah tersedia: hapus akun lalu undang ulang ke `telegram_id` baru. Daftar ulang PR #48 memulihkan baris lama **hanya bila `telegram_id` sama**, jadi dengan Telegram baru terbentuk baris pengguna baru dan riwayat tetap di baris lama. **Keputusan Q4 (2026-11-10):** alur ini cukup; fitur "ganti akun Telegram" tidak dibuat sekarang. Browser tepercaya **tidak** dijadikan jalur pemulihan dan dicabut saat akun dinonaktifkan.
   - **Temuan pemeriksaan Q4 (2026-11-10):** baris terhapus lunak tetap memegang `username` dan `phone`, sementara indeks unik (`database/migrations/2026_10_26_000101_add_kredensial_to_users_table.php:27` dan `:40`), `app/Rules/TeleponUnik.php:32-34`, dan `app/Services/Auth/KredensialService.php:149-152` menghitung baris terhapus lunak; `app/Services/Users/UserAccountService.php:84-89` tidak melepas nilai itu saat hapus. Akibatnya akun pengganti **tidak dapat** memakai username/no telepon lama. Perbaikan menjadi tugas R04-13 (T3): lepas `username`/`phone` saat hapus lunak (sejalan dengan `InvitationService::restoreUser`/`retirePlaceholder` dan minimisasi data UU PDP) + migrasi data untuk baris terhapus yang ada (butuh persetujuan manusia) + tes Q4-1..Q4-6 di rencana.

### 5. Penguncian dan batas laju web (rilis awal)
| Objek | Batas |
|---|---|
| `POST web/auth/masuk` per IP | 10/menit, 100/jam (longgar karena CGNAT seluler) |
| `POST web/auth/masuk` per identitas ter-normalisasi (hash) | 5 per 15 menit |
| Global `web/auth/*` | 300/menit (pemutus arus) |
| `POST web/auth/kode` | 5 percobaan per tantangan; 10/menit per IP; 10 per 15 menit per pengguna |
| Kirim ulang | 3 per tantangan, jeda 60 detik; maks 5 tantangan per 30 menit per pengguna |
| Penguncian kanal web | 5 gagal (sandi atau kode) -> 15 menit; terkunci lagi dalam 24 jam -> 60 menit; tidak memengaruhi Mini App |
| Notifikasi bot "percobaan gagal / dikunci" | maks 1 per jam per pengguna |
| API setelah login | `throttle:api` (60/menit per pengguna, gabungan web + Mini App), `unggah` 20/menit |

### 6. Browser tepercaya ("Ingat browser ini 30 hari")
- Kotak sukarela, **default mati**, dengan teks peringatan: "Jangan centang di komputer bersama/warnet. Sandi tetap diminta; hanya kode Telegram yang dilewati."
- Tabel `browser_tepercaya`: `id`, `user_id`, `selektor` (unik), `validator_hash` (SHA-256), `label` (browser + OS ringkas), `diverifikasi_pada`, `berlaku_sampai` = `diverifikasi_pada` + 30 hari (**tetap**, tidak bergeser saat dipakai), `terakhir_dipakai_at`, `dicabut_at`, `alasan_cabut`. Kolom nullable `browser_tepercaya_id` di `personal_access_tokens` (aditif) untuk pencabutan berantai. Maks 5 per pengguna (terpisah dari kuota sesi 5 Mini App + 3 web, Q2); kelebihan mencabut yang tertua. Sesi turunan browser tepercaya dikecualikan dari idle 12 jam (Q3).
- Dicabut otomatis saat: sandi diubah/direset; perubahan `TOKEN_SENSITIVE` (peran, unit, SPPG, status aktif, `telegram_id`); akun dihapus/dipulihkan; "keluar dari semua perangkat"; pencabutan oleh Admin; cabut satu per satu di daftar sesi. Perintah harian membersihkan yang kedaluwarsa (mengisi `dicabut_at`).
- Peran Admin **tidak boleh** memakai opsi ini (Q1, 2026-11-10): Admin selalu memasukkan kode; `ingat_browser` dari Admin diabaikan, cookie `__Host-sigap_tb` tidak pernah berlaku untuk Admin, dan perubahan peran menjadi Admin mencabut semua browser tepercaya pengguna itu (sudah tercakup pencabutan `TOKEN_SENSITIVE`).
- Audit: `auth.web.browser_tepercaya_dibuat`, `..._dipakai`, `..._dicabut` (dengan pemicu); hanya id dan tanggal, tanpa selektor/validator/token.

### 7. Audit dan notifikasi
Peristiwa baru: `auth.web.masuk_langkah1` (hasil internal, identitas di-hash), `auth.web.kode_dikirim`, `auth.web.kode_gagal`, `auth.web.masuk_berhasil` (jalur kode/browser tepercaya), `auth.web.terkunci`, `auth.web.bukan_saya`, `auth.web.keluar`, ditambah peristiwa browser tepercaya. Tidak pernah mencatat sandi, kode, token, cookie, atau identitas mentah dari akun tak dikenal. Notifikasi bot pada setiap login web berhasil.

### 8. Frontend (mode web)
- Satu basis kode `resources/miniapp/**` dengan **adapter platform** (`telegram` | `web`). Entri web terpisah (mis. `resources/miniapp/web.html`) dibangun Vite ke `public/web/`. Entri web tidak memuat `telegram-web-app.js` dan shim dev tidak ikut build produksi.
- Pengganti fitur Telegram: tema dari `prefers-color-scheme` + variabel CSS yang sama dengan `themeParams`; MainButton -> tombol aksi tetap di bawah (seluler) atau di kanan bawah form (desktop); BackButton -> tombol Kembali di header + `history`; `showConfirm`/`showAlert` -> dialog `<dialog>`; HapticFeedback -> no-op; tautan Telegram -> tautan biasa.
- `api.js` mode web: tanpa header `Authorization`, `credentials: 'same-origin'`, `X-CSRF-Token` + `X-Sigap-Klien: web`; **tidak pernah** menulis token ke `localStorage`/`sessionStorage`; 401 -> layar Masuk (tanpa login senyap, karena tidak ada initData). Mode Telegram tidak berubah.
- Responsif: satu kolom (<768 px), navigasi samping dan tabel lebar (>=1024 px). Semua layar CRUD, dasbor Chart.js, persetujuan, unggah foto (`<input type="file" accept="image/*" capture="environment">` + seret-lepas, validasi dan kompresi yang sama), dan layar draf AI (tanpa chat). Konfirmasi draf AI tetap lewat aksi pengguna yang sama.
- Layar baru: Masuk (identitas + sandi), Kode, Sesi Aktif & Browser Tepercaya (jenis Mini App/Web, label, terakhir dipakai, cabut satu, keluar semua). Layar sesi juga ditampilkan di Mini App.
- Rute hash (`#/...`) tetap dipakai, sehingga server hanya perlu melayani `/`.

### 9. nginx
- `location = /` dan aset `/web/assets/` melayani SPA statis dari `public/web/` dengan snippet baru `headers-webapp.conf`. Lokasi `/api/`, `/up`, `/miniapp/`, `/api/v1/telegram/` tidak berubah. Rute Laravel `/` di `routes/web.php` dipensiunkan atau dipersempit.
- `headers-webapp.conf` (CSP **ditegakkan**): `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; media-src 'self' blob:; worker-src 'self' blob:; frame-src 'none'; frame-ancestors 'none'; object-src 'none'; base-uri 'none'; form-action 'self'; upgrade-insecure-requests`. Bila uji staging menemukan kebutuhan atribut `style` inline, satu-satunya pelonggaran yang boleh adalah `style-src 'self' 'unsafe-inline'`; `script-src` tidak boleh dilonggarkan. Tambahan: `X-Frame-Options: DENY`, `Strict-Transport-Security: max-age=31536000; includeSubDomains` (preload diputuskan terpisah), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy: camera=(self), geolocation=(self), microphone=(), payment=(), usb=()`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, dan `Content-Security-Policy-Report-Only: require-trusted-types-for 'script'`.
- `headers-miniapp.conf` **tidak diubah** (diverifikasi dengan diff header sebelum/sesudah).

### 10. CAPTCHA
**Tidak dipasang saat rilis awal** (Q5, 2026-11-10); rilis awal hanya mengandalkan batas laju, penguncian kanal web, dan respons seragam (Keputusan 5). Bila kelak dibutuhkan (dinilai dari log audit 2 minggu pertama), CAPTCHA berupa **proof-of-work buatan sendiri tanpa pihak ketiga** (tidak ada domain tambahan di CSP, tidak ada data ke pihak lain), adaptif hanya pada `web/auth/masuk` bila: IP >= 5 gagal dalam 15 menit, identitas >= 3 gagal dalam 15 menit, atau total gagal global > 100 dalam 10 menit. Pemasangannya menjadi PBI terpisah (T3).

## Alternatif yang ditolak
- **Sanctum SPA stateful (guard `web`):** Mini App satu origin akan ikut stateful dan terkena CSRF; token transien lolos semua ability sehingga RBAC berbasis ability dan `auth:penuh` harus ditulis ulang; sesi Laravel tidak masuk hitungan batas 5 sesi PR #55.
- **Bearer di `localStorage` untuk web:** browser desktop dipakai bersama dan rentan ekstensi; HttpOnly lebih aman.
- **Telegram Login Widget sebagai pengganti sandi:** memindahkan seluruh kepercayaan ke akun Telegram (bertentangan dengan lapis sandi R-03); dapat dipertimbangkan nanti sebagai pengganti langkah identitas, bukan sandi.
- **Web di subdomain (mis. `app.sigapsppg.app`):** isolasi origin lebih baik, tetapi pengguna memutuskan akar domain (keputusan 3, ditegaskan 2026-11-10). Risiko satu origin diterima dengan mitigasi di A8 dan **dinilai ulang di tinjauan keamanan R04-11**, yang boleh merekomendasikan subdomain.
- **Batas 5 sesi gabungan web + Mini App:** ditolak di Q2 karena login web dapat mengeluarkan sesi HP.
- **CAPTCHA pihak ketiga (mis. Turnstile):** ditolak di Q5 (domain tambahan di CSP, data ke pihak ketiga, UU PDP).
- **Fitur Admin "ganti akun Telegram":** tidak dibuat sekarang (Q4).
- **Browser tepercaya yang bergeser saat dipakai:** pengguna aktif tidak pernah diminta kode lagi.
- **Lupa sandi di web:** menambah permukaan enumerasi; alur Mini App + Admin sudah ada.

## Konsekuensi dan risiko
- **Satu origin:** XSS di `/miniapp/` (CSP-nya mengizinkan skrip telegram.org) dapat menunggangi cookie web bila Mini App dibuka sebagai halaman puncak di browser yang sama. Di Telegram Web, Mini App berjalan di iframe lintas situs sehingga cookie SameSite=Strict tidak terkirim. Mitigasi: CSP kedua sisi, `h()` + pemindai statis.
- Respons seragam membuat pengguna yang salah ketik sandi menunggu kode yang tidak datang; diterima demi anti-enumerasi, dan UI memberi petunjuk.
- Komputer bersama: idle 12 jam (Q3) membatasi sesi yang lupa ditutup; pengguna web aktif tanpa browser tepercaya akan lebih sering diminta login + kode.
- Kuota terpisah (Q2): login web tidak lagi mengeluarkan sesi Mini App, tetapi jumlah sesi hidup per pengguna naik menjadi maks 8 (5 + 3).
- Sebelum R04-13 selesai, akun pengganti (Telegram baru) tidak dapat memakai username/no telepon akun lama yang terhapus lunak.
- Tanpa CAPTCHA di rilis awal (Q5), lonjakan percobaan hanya ditahan batas laju dan penguncian; dipantau dari log audit.
- Perubahan `api.js` berisiko regresi pada login senyap Mini App PR #55; wajib uji regresi dan TG-13 di 4 klien.
- Kunci baris saat penerbitan sesi (`lockForUpdate`) wajib diuji ulang di MySQL 8.4 staging dengan login web dan Mini App serentak.
- Pengguna yang kehilangan akun Telegram tidak dapat masuk web (kecuali Admin memulihkan); ini disengaja.
- HSTS `includeSubDomains` memaksa HTTPS di semua subdomain; pastikan tidak ada subdomain HTTP sebelum diaktifkan.
