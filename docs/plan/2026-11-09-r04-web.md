# R-04 Akses Web (Tier T3) - Tahap 0: Rencana

Tanggal: 2026-11-09 · Status: rencana, **belum ada kode** · ADR: `docs/decisions/2026-11-09-akses-web.md` (Diusulkan)
Fitur terkait: No 1 Data Pengguna (Login Akun). Fitur 2-16 hanya mendapat kanal web; ruang lingkup Subbab 5.2 tidak bertambah.
Acuan: keputusan pengguna R-04 (6 butir), ADR sesi PR #55, rencana R-03 (`docs/plan/2026-10-26-r03-login-kredensial.md`), PR #48 (daftar ulang).
Berkas acuan `claude/revisi-r04-akses-web.md` dan `claude/revisi-r03-login-kredensial.md` tidak ada di repo dan tidak dipakai.

## Tujuan
1. Semua fitur kerja (CRUD, dasbor, persetujuan, unggah foto, layar draf AI) bisa dipakai di `https://sigapsppg.app/` dari browser desktop dan seluler. Chat Agen AI di web ditunda; notifikasi tetap lewat bot.
2. Login web = identitas + sandi + kode sekali pakai dari bot, atau tanpa kode di browser tepercaya (30 hari tetap).
3. Mini App `/miniapp/`, login senyap PR #55, perangkat tepercaya bot, dan header Mini App **tidak melemah dan tidak berubah perilakunya**.
4. Tanpa registrasi mandiri; akun tetap dari undangan Admin + aktivasi di bot.

## Ringkasan desain (detail di ADR)
- Dua jalur, satu jenis token Sanctum: Bearer (Mini App) dan cookie HttpOnly `__Host-sigap_sesi` (web, ability `klien:web`). Jalur saling menolak token milik jalur lain. Header `Authorization` ada -> cookie diabaikan.
- CSRF tiga lapis untuk jalur cookie: SameSite=Strict + Origin persis + `X-CSRF-Token` (HMAC terikat sesi) dan `X-Sigap-Klien: web`. `config/cors.php` eksplisit tanpa origin.
- Respons langkah 1 seragam (anti-enumerasi). Penguncian kanal web terpisah dari Mini App.
- Browser tepercaya: tabel baru, token 256-bit ter-hash, 30 hari tetap, maks 5, dicabut otomatis; Admin diusulkan tidak boleh.
- Sesi web masuk batas 5 sesi gabungan dan mengikuti 90/30/180 hari PR #55.
- Frontend: adapter platform `telegram|web`, entri web tanpa `telegram-web-app.js`, build ke `public/web/`.
- nginx: `/` melayani SPA web dengan CSP ditegakkan + HSTS + XFO DENY + COOP/CORP; `headers-miniapp.conf` tidak disentuh.

## Batas laju dan CAPTCHA (usulan)
| Objek | Batas |
|---|---|
| `web/auth/masuk` per IP | 10/menit, 100/jam |
| `web/auth/masuk` per identitas (hash ter-normalisasi) | 5 per 15 menit |
| `web/auth/*` global | 300/menit |
| `web/auth/kode` | 5 percobaan per tantangan; 10/menit per IP; 10 per 15 menit per pengguna |
| Kirim ulang kode | 3 per tantangan, jeda 60 detik; maks 5 tantangan per 30 menit per pengguna (config R-03) |
| Penguncian kanal web | 5 gagal -> 15 menit; berulang dalam 24 jam -> 60 menit; Mini App tidak ikut terkunci |
| Notifikasi bot gagal/kunci | maks 1 per jam per pengguna |
| API setelah login | `throttle:api` 60/menit per pengguna (gabungan), `unggah` 20/menit |

CAPTCHA **tidak dipasang saat rilis awal**. Aktif adaptif hanya pada `web/auth/masuk` bila IP >= 5 gagal dalam 15 menit, identitas >= 3 gagal dalam 15 menit, atau gagal global > 100 dalam 10 menit. Ambang ditinjau ulang dari log audit 2 minggu pertama.

## Daftar tes keamanan (wajib sebelum merge)
Backend (feature test):
- S-01 Token Mini App dikirim sebagai cookie web -> 401. S-02 Token `klien:web` dikirim sebagai Bearer -> 401.
- S-03 Bearer tidak sah + cookie web sah -> 401 (cookie diabaikan bila ada `Authorization`).
- S-04 Jalur cookie: metode pengubah tanpa/salah `X-CSRF-Token`, tanpa `X-Sigap-Klien`, `Origin` asing atau kosong -> ditolak; CSRF milik sesi lain -> ditolak.
- S-05 `web/auth/masuk` identik (status, bentuk JSON, header) untuk akun tak ada, sandi salah, akun nonaktif, kanal web terkunci, dan sandi benar; kode terkirim (Http::fake) hanya saat sandi benar; selisih waktu respons dalam toleransi.
- S-06 Kode: kedaluwarsa 5 menit, sekali pakai (replay gagal), 5 percobaan menghanguskan tantangan, tersimpan ter-hash (tidak ada kode mentah di DB/log/audit), `tantangan_id` tiruan atau milik orang lain -> galat seragam.
- S-07 5 gagal di web mengunci kanal web saja; login Mini App (initData + sandi) tetap berhasil.
- S-08 Browser tepercaya: lewati kode hanya bila sandi benar; cookie milik A dipakai untuk akun B -> langkah kode; lewat 30 hari -> langkah kode; `berlaku_sampai` tidak bergeser saat dipakai; validator tersimpan SHA-256; tidak muncul di audit.
- S-09 Pencabutan otomatis browser tepercaya + sesi web: ubah sandi, reset, perubahan peran/unit/SPPG/status/`telegram_id`, hapus/pulihkan akun, keluar semua, Admin cabut, cabut satu; sesi turunan browser ikut dicabut.
- S-10 Admin dengan `ingat_browser=true` -> sesuai jawaban Q1 (usulan: diabaikan, tidak dibuat).
- S-11 Batas 5 sesi gabungan: login ke-6 (web atau Mini App) mencabut sesi paling lama tidak dipakai; uji serentak di MySQL 8.4 staging.
- S-12 Masa sesi web 90 hari sliding / Admin 30 / absolut 180 (time travel); Max-Age cookie mengikuti.
- S-13 RBAC regresi: sampel endpoint tiap fitur 2-16 memberi 403 untuk peran tanpa hak lewat sesi web; `X-SPPG-Id` divalidasi `ResolveSppgAktif`.
- S-14 Batas laju 429 di ambang; CAPTCHA diminta setelah ambang (bila diaktifkan).
- S-15 Atribut `Set-Cookie`: prefiks `__Host-`, Secure, HttpOnly, SameSite=Strict, Path=/, tanpa Domain.
- S-16 Logout web mencabut token server dan menghapus cookie (`Max-Age=0`); cookie lama dipakai lagi -> 401.
- S-17 Draf AI lewat web: konfirmasi tetap aksi pengguna; tanpa konfirmasi tidak ada penulisan.
- S-18 Unggah foto lewat web: validasi MIME/ukuran/EXIF sama, CSRF wajib, `throttle:unggah`.
- S-19 Tombol bot "Bukan saya" membatalkan tantangan dan tercatat di audit; tidak mengunci akun.
- S-20 CORS: preflight dari origin asing ke `/api/*` tidak mendapat `Access-Control-Allow-Origin` atau `Allow-Credentials`.
- S-21 Fiksasi sesi: `__Host-sigap_pra` dihapus dan CSRF diganti setelah login.

Frontend dan regresi Mini App:
- M-01 Semua `node --test resources/miniapp/tests/*.test.js` lulus; mode Telegram tetap memuat `telegram-web-app.js`, Bearer di `localStorage`, dan login senyap 401 PR #55 tidak berubah (tes yang ada tidak boleh diubah untuk meloloskan).

- N-02 Halaman `/` yang dibingkai origin lain diblokir; OWASP ZAP baseline pada staging tanpa temuan High.

## Risiko
- Regresi Mini App dari perubahan `api.js`/adapter: dimitigasi R04-5 terpisah, opus, M-01..M-04.
- Satu origin web + Mini App (keputusan 3): XSS di salah satu dapat menunggangi sesi web di browser yang sama; dimitigasi CSP dan pemindai statis.
- Respons seragam merugikan UX saat salah ketik sandi; diterima dengan petunjuk di UI.
- Batas 5 sesi gabungan dapat mengeluarkan sesi Mini App lama (Q2).
- Pengguna yang kehilangan akun Telegram bergantung pada Admin (Q4). Daftar ulang PR #48 hanya memulihkan baris dengan `telegram_id` sama. Perlu dicek apakah username/no telepon lama masih dipegang baris terhapus lunak dan menghalangi akun baru.
- CSP `style-src 'self'` tanpa `unsafe-inline` mungkin memblokir gaya komponen; uji Report-Only dulu di staging.
- Beban baru pada bot (kode + notifikasi login) dibatasi `telegram-out` 25/detik.

## Pertanyaan terbuka untuk pengguna (maks 5)
1. **Q1 Admin dan "Ingat browser ini":** usulan PM: Admin **tidak boleh** (selalu memasukkan kode, karena akun Admin paling berdampak). Setuju, atau Admin boleh dengan masa lebih pendek (mis. 7 hari)?
2. **Q2 Batas 5 sesi:** gabungan web + Mini App (usulan, sesuai keputusan 6) atau kuota terpisah (mis. 5 Mini App + 3 web) agar login web tidak mengeluarkan sesi HP?
3. **Q3 Komputer bersama:** sesi web mengikuti 90 hari sliding (keputusan 6) apa adanya, atau ditambah batas idle khusus web (usulan: 12 jam tidak aktif, kecuali browser tepercaya) agar sesi yang lupa ditutup di warnet tidak bertahan 90 hari?
4. **Q4 Kehilangan akun Telegram:** cukup alur yang ada (Admin nonaktifkan, lalu hapus + undang ulang ke Telegram baru sehingga terbentuk baris pengguna baru), atau perlu fitur baru Admin "ganti akun Telegram" (T3, verifikasi tatap muka) agar riwayat tetap pada akun yang sama?
5. **Q5 CAPTCHA:** bila ambang terlampaui, pakai penyedia pihak ketiga (mis. Cloudflare Turnstile: domain tambahan di CSP, data ke pihak ketiga, pertimbangan UU PDP) atau tantangan proof-of-work buatan sendiri tanpa pihak ketiga (usulan PM)?
