# R-04 Akses Web (Tier T3) - Tahap 0: Rencana

Tanggal: 2026-11-09 · Diperbarui: 2026-11-10 (keputusan Q1-Q5) · Status: rencana disetujui, **belum ada kode** · ADR: `docs/decisions/2026-11-09-akses-web.md` (**Diterima** 2026-11-10)
Fitur terkait: No 1 Data Pengguna (Login Akun). Fitur 2-16 hanya mendapat kanal web; ruang lingkup Subbab 5.2 tidak bertambah.
Acuan: keputusan pengguna R-04 (6 butir), ADR sesi PR #55, rencana R-03 (`docs/plan/2026-10-26-r03-login-kredensial.md`), PR #48 (daftar ulang).
Berkas acuan `claude/revisi-r04-akses-web.md` dan `claude/revisi-r03-login-kredensial.md` tidak ada di repo dan tidak dipakai.

## Tujuan
1. Semua fitur kerja (CRUD, dasbor, persetujuan, unggah foto, layar draf AI) bisa dipakai di `https://sigapsppg.app/` dari browser desktop dan seluler. Chat Agen AI di web ditunda; notifikasi tetap lewat bot.
2. Login web = identitas + sandi + kode sekali pakai dari bot, atau tanpa kode di browser tepercaya (30 hari tetap; **bukan untuk Admin**).
3. Mini App `/miniapp/`, login senyap PR #55, perangkat tepercaya bot, dan header Mini App **tidak melemah dan tidak berubah perilakunya**.
4. Tanpa registrasi mandiri; akun tetap dari undangan Admin + aktivasi di bot.

## Ringkasan desain (detail di ADR)
- Dua jalur, satu jenis token Sanctum: Bearer (Mini App) dan cookie HttpOnly `__Host-sigap_sesi` (web, ability `klien:web`). Jalur saling menolak token milik jalur lain. Header `Authorization` ada -> cookie diabaikan.
- CSRF tiga lapis untuk jalur cookie: SameSite=Strict + Origin persis + `X-CSRF-Token` (HMAC terikat sesi) dan `X-Sigap-Klien: web`. `config/cors.php` eksplisit tanpa origin.
- Respons langkah 1 seragam (anti-enumerasi). Penguncian kanal web terpisah dari Mini App.
- Browser tepercaya: tabel baru, token 256-bit ter-hash, 30 hari tetap, maks 5, dicabut otomatis; **Admin tidak boleh** (Q1).
- Kuota sesi terpisah (Q2): maks 5 Mini App + maks 3 web. Login Mini App ke-6 hanya mencabut sesi Mini App terlama; login web ke-4 hanya mencabut sesi web terlama. Batas keras di kode (5 dan 3), env hanya boleh mengetatkan.
- Masa sesi web (Q3): idle 12 jam untuk sesi web biasa (termasuk semua sesi web Admin); sesi web dari browser tepercaya mengikuti 90 hari sliding tetapi tidak melewati `berlaku_sampai` browser itu; semua tetap dibatasi absolut 180 hari, Admin 30 hari sliding.
- Frontend: adapter platform `telegram|web`, entri web tanpa `telegram-web-app.js`, build ke `public/web/`.
- nginx: `/` melayani SPA web dengan CSP ditegakkan + HSTS + XFO DENY + COOP/CORP; `headers-miniapp.conf` tidak disentuh.

## Pemeriksaan Q4: username/no telepon baris terhapus lunak (read-only, 2026-11-10)
Hasil: **menghalangi**. Hapus + undang ulang ke Telegram baru membentuk baris pengguna baru, tetapi baris lama yang terhapus lunak tetap memegang `username` dan `phone`, dan semua penjaga keunikan menghitung baris terhapus lunak:
- `database/migrations/2026_10_26_000101_add_kredensial_to_users_table.php:27` indeks unik biasa `users.username` (tanpa mempertimbangkan `deleted_at`).
- `database/migrations/2026_10_26_000101_add_kredensial_to_users_table.php:40` indeks unik biasa `users_phone_unique`.
- `app/Rules/TeleponUnik.php:32-34` sengaja menghitung akun terhapus lunak ("sesuai indeks unik"); dipakai `app/Http/Requests/Pengguna/PenggunaRequest.php:42` -> Admin tidak dapat mengisi no telepon lama pada akun/placeholder baru ("No telepon sudah dipakai akun lain.").
- `app/Services/Auth/KredensialService.php:149-152` `usernameDipakaiAkunLain` memakai `DB::table('users')` tanpa filter `deleted_at` -> aktivasi akun baru dengan username lama ditolak "Username tidak tersedia".
- `app/Services/Users/UserAccountService.php:84-89` hapus lunak tidak melepas `username`/`phone` (hanya `telegram_id` yang sengaja dipertahankan untuk daftar ulang PR #48).
- Pembanding: jalur daftar ulang (`telegram_id` sama) sudah melepas nilai unik: `app/Services/Users/InvitationService.php:399-406` (username -> null) dan `:415-421` (`retirePlaceholder`, phone -> null). Tidak ada tes yang mencakup skenario Telegram baru (`tests/Feature/Master/InvitationServiceTest.php:239` hanya menguji `telegram_id` sama).

Tindak lanjut: tugas perbaikan **R04-13 (T3)**, karena memerlukan migrasi yang mengubah data baris terhapus lunak dan mengubah semantik keunikan identitas login. Usulan perbaikan (diputuskan saat implementasi, butuh persetujuan manusia untuk migrasi data):
- (a, usulan PM) Saat hapus lunak, lepaskan `username` dan `phone` (set `null`, sejalan dengan jalur daftar ulang dan prinsip minimisasi data UU PDP); `telegram_id` tetap. Migrasi data sekali jalan mengosongkan `username`/`phone` pada baris yang sudah terhapus lunak (nilai lama tidak disimpan ulang di mana pun). Daftar ulang `telegram_id` sama tetap berfungsi karena `restoreUser` sudah mengisi ulang dari placeholder/aktivasi.
- (b) Kolom tergenerasi `username_aktif`/`phone_aktif` = nilai bila `deleted_at IS NULL`, indeks unik dipindah ke kolom itu, penjaga validasi mengabaikan baris terhapus. Lebih rumit dan baris terhapus tetap menyimpan data pribadi.

Tes wajib R04-13 (feature test): Q4-1 hapus akun A (username `siti`, phone `+628...`) lalu undang ulang ke `telegram_id` baru -> aktivasi dengan username `siti` berhasil; Q4-2 Admin membuat akun/placeholder dengan no telepon milik baris terhapus lunak -> berhasil; Q4-3 login identitas `siti` dan no telepon itu masuk ke akun baru, bukan baris lama; Q4-4 daftar ulang `telegram_id` sama (PR #48) tetap memulihkan baris lama dan tidak bentrok dengan akun baru; Q4-5 username/phone milik akun **aktif** atau **nonaktif (belum dihapus)** tetap ditolak; Q4-6 migrasi data idempoten dan tidak menyentuh baris aktif.

Kebutuhannya dinilai dari log audit 2 minggu pertama setelah rilis; pemasangan menjadi PBI terpisah (T3).

## Daftar tes keamanan (wajib sebelum merge)
Backend (feature test):
- S-01 Token Mini App dikirim sebagai cookie web -> 401. S-02 Token `klien:web` dikirim sebagai Bearer -> 401.
- S-03 Bearer tidak sah + cookie web sah -> 401 (cookie diabaikan bila ada `Authorization`).
- S-04 Jalur cookie: metode pengubah tanpa/salah `X-CSRF-Token`, tanpa `X-Sigap-Klien`, `Origin` asing atau kosong -> ditolak; CSRF milik sesi lain -> ditolak.
- S-05 `web/auth/masuk` identik (status, bentuk JSON, header) untuk akun tak ada, sandi salah, akun nonaktif, kanal web terkunci, dan sandi benar; kode terkirim (Http::fake) hanya saat sandi benar; selisih waktu respons dalam toleransi.
- S-06 Kode: kedaluwarsa 5 menit, sekali pakai (replay gagal), 5 percobaan menghanguskan tantangan, tersimpan ter-hash (tidak ada kode mentah di DB/log/audit), `tantangan_id` tiruan atau milik orang lain -> galat seragam.
- S-07 5 gagal di web mengunci kanal web saja; login Mini App (initData + sandi) tetap berhasil.
- S-08 Browser tepercaya: lewati kode hanya bila sandi benar; cookie milik A dipakai untuk akun B -> langkah kode; lewat 30 hari -> langkah kode; `berlaku_sampai` tidak bergeser saat dipakai; validator tersimpan SHA-256; tidak muncul di audit; maks 5 per pengguna (ke-6 mencabut yang tertua) dan tidak memengaruhi kuota sesi.
- S-09 Pencabutan otomatis browser tepercaya + sesi web: ubah sandi, reset, perubahan peran/unit/SPPG/status/`telegram_id`, hapus/pulihkan akun, keluar semua, Admin cabut, cabut satu; sesi turunan browser ikut dicabut.
- S-10 (Q1) Admin dengan `ingat_browser=true` -> sesi web terbit, tetapi tidak ada baris `browser_tepercaya` dan tidak ada cookie `__Host-sigap_tb`; cookie browser tepercaya sah milik pengguna yang kemudian menjadi Admin -> dicabut dan langkah kode tetap diminta.
- S-11 (Q2) Kuota terpisah: login Mini App ke-6 mencabut sesi Mini App terlama tanpa menyentuh sesi web; login web ke-4 mencabut sesi web terlama tanpa menyentuh sesi Mini App; env yang mencoba menaikkan batas di atas 5/3 diabaikan; uji serentak di MySQL 8.4 staging.
- S-12 Masa sesi web 90 hari sliding / Admin 30 / absolut 180 (time travel) untuk sesi browser tepercaya, tidak melewati `berlaku_sampai` browser; Max-Age cookie mengikuti.
- S-13 RBAC regresi: sampel endpoint tiap fitur 2-16 memberi 403 untuk peran tanpa hak lewat sesi web; `X-SPPG-Id` divalidasi `ResolveSppgAktif`.
- S-14 (Q5) Batas laju 429 di ambang; tidak ada endpoint, header, atau aset CAPTCHA di rilis awal.
- S-15 Atribut `Set-Cookie`: prefiks `__Host-`, Secure, HttpOnly, SameSite=Strict, Path=/, tanpa Domain.
- S-16 Logout web mencabut token server dan menghapus cookie (`Max-Age=0`); cookie lama dipakai lagi -> 401.
- S-17 Draf AI lewat web: konfirmasi tetap aksi pengguna; tanpa konfirmasi tidak ada penulisan.
- S-18 Unggah foto lewat web: validasi MIME/ukuran/EXIF sama, CSRF wajib, `throttle:unggah`.

## Risiko
- Regresi Mini App dari perubahan `api.js`/adapter: dimitigasi R04-5 terpisah, opus, M-01..M-04.
- Satu origin web + Mini App (keputusan 3): XSS di salah satu dapat menunggangi sesi web di browser yang sama; dimitigasi CSP dan pemindai statis; dinilai ulang di R04-11 (boleh merekomendasikan subdomain).
- Respons seragam merugikan UX saat salah ketik sandi; diterima dengan petunjuk di UI.
- Kuota terpisah (Q2) menaikkan jumlah sesi hidup per pengguna menjadi maks 8 (5 + 3); diimbangi idle 12 jam untuk web biasa dan daftar sesi + cabut.
- Idle 12 jam (Q3) bergantung pada ketelitian `last_used_at`; jeda tulis token web harus <= 15 menit (beban tulis DB sedikit naik).
- Kehilangan akun Telegram (Q4) tetap bergantung pada Admin; sebelum R04-13 selesai, username/no telepon lama terkunci oleh baris terhapus lunak sehingga akun pengganti harus memakai identitas lain.
- Migrasi data R04-13 mengubah baris terhapus lunak (tidak dapat dibalik untuk nilai yang dikosongkan); butuh persetujuan manusia dan cadangan DB staging sebelum dijalankan.
- Tanpa CAPTCHA di rilis awal (Q5), perlindungan brute force bergantung pada batas laju, penguncian kanal web, dan respons seragam; pantau log audit 2 minggu pertama.
- CSP `style-src 'self'` tanpa `unsafe-inline` mungkin memblokir gaya komponen; uji Report-Only dulu di staging.
- Beban baru pada bot (kode + notifikasi login) dibatasi `telegram-out` 25/detik.
- Pemakaian Opus terkonsentrasi di G1-G3, G5, G6; bila batas pemakaian tercapai, gelombang bergeser satu slot (2-3 hari) dan cadangan 15-18 Des dipakai.
