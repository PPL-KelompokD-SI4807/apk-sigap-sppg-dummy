Tanggal: 2026-11-14. Status: rancangan disetujui pengguna; PR1 selesai (commit fa6baf1), PR2 dst. menunggu PR1 ter-merge.
Tujuan: web desktop memakai modul yang sama dengan Mini App tanpa mengubah perilaku Mini App (Bearer untuk Telegram, cookie HttpOnly + CSRF untuk web).

## 2) Arsitektur lapisan klien
Facade `core/transport.js` = satu-satunya pintu modul ke klien API.
- Mini App (bawaan): re-export `api.js` (Bearer), perilaku tidak berubah.
- Web: `core/transport-web.js` di atas `api-web.js` (cookie + CSRF di memori, tanpa storage, tanpa antrean offline).
- Dipilih saat build: plugin Vite `resolveId` pada `vite build --mode web` mengganti transport.js dengan transport-web.js. Bundel kedua mode tidak saling memuat.
- Bentuk: api{get,post,put,del}, request, fetchList, submitWithQueue, uploadMultipart, newKey, ApiError, flushQueue, getToken, onAuthRequired/onSesiBerakhir/onPerluLoginUlang/onSppgDiperlukan. Navigasi, tombol native, dan tema tetap lewat platform.js, router.js, ui.js, theme.js.
- Pengecualian impor langsung: core/auth.js, main.js (Mini App); web-main.js, modules/auth-web/layar.js, modules/sesi/layar.js (web).

## 4) Risiko dan mitigasi
- Regresi Mini App saat migrasi impor: PR refactor murni, tes statis impor, tes regresi yang ada.
- Token bocor ke storage web: api-web.test.js + uji bundel web tanpa localStorage/Authorization.
- Bundel membengkak: tes gzip relatif (+10% dari garis dasar) untuk kedua mode.
- CSRF pada multipart dan PUT via _method: sudah ada di api-web.js, uji dengan Blob.
- Event sesi berbeda (auth-required vs sesi-habis): dipetakan di facade.
- Fitur Telegram-only bocor ke web (share, draf, ?r=): guard platform per rute.
- Hak akses: klien hanya membaca peta hak server, tidak menyalin matriks.
